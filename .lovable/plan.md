## Goal

When someone types a job title, the description field fills itself with a well-structured JD draft generated by AI — instead of being written by hand.

## Where it applies

1. New position dialog (`src/routes/positions.tsx`)
2. Edit requirement dialog (`src/components/edit-position-dialog.tsx`)
3. New job posting (`src/routes/posting.new.tsx`)
4. Client "Upload JD" form (`src/routes/client.upload.tsx`)

## Behaviour

- Auto-trigger: when the title field loses focus (or after a short pause in typing) and the description is still empty, generation starts automatically and streams into the textarea.
- Never overwrites: if the user already typed or pasted a description (or it was prefilled from a linked position/parsed JD), nothing is auto-replaced.
- Manual control: a small "Generate with AI" / "Regenerate" button next to the Description label, with a spinner while running, so users can redo it after changing the title.
- Context-aware: the prompt also uses whatever the form already has — location, experience, salary range, skills/tags, client/company name, employment type — so the draft is specific rather than generic.
- Output: markdown-ish plain text with About the role, Key responsibilities, Required skills, Nice to have, and (when experience/comp exist) a short What we offer section. Fully editable afterwards.
- Failure handling: toast on error, description left untouched. Rate limit (429) and out-of-credits (402) get their own clear messages.

## Technical notes

- New server function `src/lib/jd-generate.functions.ts` → `generateJobDescription`, validated with Zod (title required; optional location, experience, salary, skills, employmentType, companyName, seniority hint).
- Calls Lovable AI Gateway (`https://ai.gateway.lovable.dev/v1/chat/completions`) with `google/gemini-3.6-flash` — fast and cheap for this; `LOVABLE_API_KEY` read inside the handler, server-side only. Same pattern as the existing `src/lib/jd-extract.functions.ts`.
- Shared client hook `src/hooks/use-jd-autofill.ts` encapsulating debounce, "only if empty" guard, in-flight state, and last-generated-title tracking so the four forms stay consistent and no duplicate calls fire.
- Small presentational `GenerateDescriptionButton` used above each Description textarea.
- No database or schema changes.
